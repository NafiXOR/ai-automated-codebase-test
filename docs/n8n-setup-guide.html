n8n Automated Workflow Setup

Follow these steps to run n8n locally with Docker and import the starter workflow included in this repo. Check off each step as you go — progress is saved in this browser.

Docker Compose Self-hosted ~10 min

• Prerequisites

  • Docker and Docker Compose (bundled with Docker Desktop)
  • curl or any HTTP client, to test the webhook later (optional)
docker --version
docker compose version

1 Configure environment variables

Copy the example env file:

cp .env.example .env

Open .env and set a real login for the n8n UI:

N8N_BASIC_AUTH_USER=admin
N8N_BASIC_AUTH_PASSWORD=choose-a-strong-password
.env is git-ignored — your credentials are never committed.

2 Start n8n

From the repo root:

docker compose up -d

Check that the container is healthy:

docker compose ps
docker compose logs -f n8n

3 Log in to the n8n editor

Open http://localhost:5678 and log in with the N8N_BASIC_AUTH_USER / N8N_BASIC_AUTH_PASSWORD you set in .env.

4 Import the starter workflow

  1. In the n8n editor, click Workflows in the left sidebar, then Add workflow.
  2. Click the ⋯ menu (top right) → Import from File.
  3. Select workflows/starter-workflow.json from this repo.
  4. Click Save, then toggle Active (top right).
NodePurpose
WebhookTrigger — listens on POST /webhook/starter-webhook
Set Response DataAdds a message and receivedAt timestamp
Respond to WebhookReturns the processed data as JSON

5 Test the workflow

With the workflow active, trigger it:

curl -X POST http://localhost:5678/webhook/starter-webhook \
  -H "Content-Type: application/json" \
  -d '{"hello": "world"}'

You should get back JSON containing your original payload plus message and receivedAt. If nothing responds, open the workflow and check Executions for errors.

6 Build your own automation

Use the starter workflow as a template:

  • Replace Webhook with whatever should kick off your automation (schedule, form, another app's trigger node…)
  • Replace Set Response Data with the real processing steps (HTTP Request, Code, If, database nodes…)
  • Replace Respond to Webhook with a notification step (Slack, Email, Discord…) if it doesn't need to return an HTTP response

Export what you build back into this repo: ⋯ menu → Download, save into workflows/.

• Day-to-day operations

Stop n8ndocker compose stop
Start it againdocker compose start
Stop & remove container (data persists)docker compose down
View logsdocker compose logs -f n8n
Update to latest imagedocker compose pull && docker compose up -d
Full reset ⚠️ deletes workflows/credentialsdocker compose down -v

• Troubleshooting

Port 5678 already in use — stop whatever else is using it, or change the left-hand port in ports: in docker-compose.yml (e.g. "5679:5678") and update WEBHOOK_URL.
Can't log in — confirm .env exists and was edited before docker compose up -d. Run docker compose up -d --force-recreate after changing .env.
Webhook returns 404 — make sure the workflow is toggled Active, and use the production URL (/webhook/...), not the test URL (/webhook-test/...) shown while editing.
Losing data after restart — docker compose down -v deletes the n8n_data volume; plain docker compose down does not.
